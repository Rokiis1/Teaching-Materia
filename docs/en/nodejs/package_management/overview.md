# Overview

Package management provides a structured way to add, track, update, and remove external packages used by a Node.js project. Instead of manually downloading reusable code and copying it into a project, a package manager records dependency information, installs the required package files, and provides commands for maintaining them. Project files such as `package.json` and lockfiles preserve this information so dependency installations can be understood and reproduced.

The **Package Management** module develops from the foundations of npm and project dependencies to alternative package-management workflows with pnpm. It establishes how packages are discovered and installed, how dependency versions and categories are recorded, how installed packages are maintained, and how different package managers can use the same project dependency model while managing package files differently.

**Level 1** introduces the foundations of package management with **npm**. It covers creating `package.json`, distinguishing **packages, dependencies, and package managers**, and understanding the relationship between npm and the **npm registry**, including how published packages can be explored through the npm website. It then develops the basic dependency workflow through **package installation**, **semantic versioning**, `dependencies` and `devDependencies`, `node_modules`, and `package-lock.json`. The level also introduces commands for viewing, updating, and removing packages, defines reusable project commands with **npm scripts**, and explains the difference between **local and global packages**.

**Level 2** builds on the npm workflow by introducing **pnpm** and explaining why a project might choose an alternative package manager. It shows how pnpm continues to use the npm registry and familiar project metadata while providing its own commands and `pnpm-lock.yaml`. The level then explains pnpm's **content-addressable store**, how reusable package content can be shared across projects, how hard links and symbolic links connect dependencies into a project, and how its stricter dependency layout distinguishes **direct and transitive dependencies**.

Together, these concepts provide a foundation for managing external packages in Node.js projects with a clearer understanding of both the dependency information recorded by a project and the tools that manage it. They support a progression from the standard npm workflow to alternative package-management strategies, preparing for later material on reproducible installations, dependency security, and package distribution.
